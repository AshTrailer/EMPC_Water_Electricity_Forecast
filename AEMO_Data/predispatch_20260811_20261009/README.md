# AEMO 30 分钟预调度电价 60 天(2026-08-11 至 2026-10-09)

**本目录是为与平级的 `AEMO_Data/pd7day_20260811_20261009` 在同一窗口、同一 lead 上
直接对比而补抓的 60 天 PREDISPATCH,不是 `AEMO_Data/predispatch_120d_20260201_20260601`
那套 120 天的子集。** 那套窗口是 2026-02-01 到 2026-06-01,与本目录
**交集为空**,不能当作它的切片,也不能拼成一条连续时间轴。

## 一、窗口与用途

| 目录 | 产品 | 窗口 | 天数 | 每天 run 数 | 最大 lead |
|---|---|---|---|---|---|
| `predispatch_120d_20260201_20260601` | PREDISPATCH | 2026-02-01 至 06-01 | 120 | 48 | 39.0 小时 |
| **本目录** | PREDISPATCH | **2026-08-11 至 10-09** | **60** | **48** | **39.0 小时** |
| `pd7day_20260811_20261009` | PD7DAY | 2026-08-11 至 10-09 | 60 | 3 | 183.0 小时 |

本目录与 `pd7day_20260811_20261009` **窗口完全一致**,可以在同一时间轴、同一 lead 上
逐点对比;两者的差异是发布节奏(48 次/天 对 3 次/天)与 horizon 长度(39.0 小时 对 183.0 小时)。

## 二、时区口径

**全部时间戳是 NEM 时间(AEST,UTC+10,全年不随夏令时偏移),文件中没有时区后缀。**
解析时显式关闭了 Australia/Sydney 本地时间换算(`aemo_config.USE_AUS_LOCAL_TIME = False`)。

## 三、数据来源

`Predispatch_Reports` 这一族**没有日报,归档是 7 天区间的周包**。本目录拼了两个来源:

1. **ARCHIVE 周包**(`Reports/ARCHIVE/Predispatch_Reports/PUBLIC_PREDISPATCH_YYYYMMDD_YYYYMMDD.zip`)
   覆盖 2026-08-11 至 2026-09-26,共 7 个周包。
2. **CURRENT 单批报表**(`Reports/CURRENT/Predispatch_Reports/PUBLIC_PREDISPATCH_<eff>_<gen>_LEGACY.zip`)
   补齐 2026-09-27 至 2026-10-09,共 624 个 run。

**为什么要分两个来源**:ARCHIVE 落后约两周,`PUBLIC_PREDISPATCH_20260927_20261003.zip` 与
`PUBLIC_PREDISPATCH_20261004_20261010.zip` 都返回 **HTTP 404**,而 CURRENT 仍有这一段单批报表。

## 七、是否钳位

**未做任何钳位。** 负价、零价、极值原样保留。同样未做插值、未补齐缺失时刻、未截断 horizon。

## 八、怎么用它跟 pd7day 对比

```
lead_minutes = (target_datetime - effective_time) 换算成分钟
```

两个目录的 `effective_time` / `target_datetime` 命名与语义相同,直接按
`(effective_time, region_id, target_datetime)` 对齐即可。注意 PD7DAY 每天只有 3 个
发布点、horizon 到 183 小时,而本目录每天 48 个、到 39 小时,能对齐的是
**共同覆盖的那部分目标时刻**(最多 39 小时以内)。

## 九、已知不足

1. 窗口只有 60 天,与那套 120 天**交集为空**。
2. 2026-09-27 至 2026-10-09 来自 CURRENT,而 CURRENT 是滚动目录;这部分不像 ARCHIVE 那样
   有长期留存保证。
3. horizon 最长 39.0 小时,不能覆盖 PD7DAY 的 39 到 183 小时段。
4. 未取 Adjusted_Prices,不含事后价格修订。
