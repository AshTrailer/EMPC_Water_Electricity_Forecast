# Basic 1.2

真正的滚动时域经济 MPC：单水箱、单台固定流量二进制泵、5 分钟采样、288 步（24 小时）预测时域。它保留 Basic 1.1.1 的水位硬约束、电费和启停成本，但没有 `terminal_min_m`，也不要求预测终点恢复到 2.30 m。

> **实现边界：**这是离线 perfect-information 验证。历史 VIC1 实际价格在每个预测窗中被当作已知未来价格；它验证控制器和时间对齐，不验证电价预测器。

## 一、Basic 1.2 说明

Basic 1.2 是一个用于单水箱、单台固定流量泵的价格驱动经济 MPC。控制变量 `u(k)` 只能取 0 或 1，分别表示水泵关闭或开启；开启时流量为 0.050 m³/s、功率为 46 kW。控制器利用未来 24 小时的电价和用水需求，在满足水位 1.40-3.37 m 硬约束的前提下，最小化电能成本与启停成本。

水箱模型为：

```text
x(k+1) = x(k) + dt/area * (pump_flow*u(k) - demand(k))
```

其中采样间隔 `dt = 300 s`，预测时域 `N = 288`。Basic 1.2 的关键不是一次求出整天调度后照表执行，而是闭环滚动：每个 5 分钟采样点都读取当前水位，重新优化未来 288 步，只执行最优序列的第一个动作；随后用 Decision 返回的实际泵流量和当前需求更新水位，再把预测窗向前移动一步。

默认运行显示 288 个区间，因此必须准备 575 个连续输入点。历史价格连续跨日读取；每日 288 点 Richmond 需求曲线则按日循环到相同长度。该版本仍使用 mock Decision 理想执行器，尚未连接真实泵组选择模块，也没有接入在线电价预测器。

## 二、从 Basic 1.1.1 到 Basic 1.2 的更新

Basic 1.2 以被 Git 跟踪的 `MPC/Basic 1.1.1` 为完整基线创建，没有修改或覆盖原目录。Basic 1.1.1 的主仿真器已经具有逐步调用控制器的结构，但需求仍是恒定 0.025 m³/s，而且 `run_two_day_comparison.m` 另有只求解一次整天计划的 `optimize_one_day` 路径。Basic 1.2 对这些不足作了以下更新：

| 项目 | Basic 1.1.1 | Basic 1.2 |
|---|---|---|
| 用水需求 | 恒定 0.025 m³/s | 25 L/s 基础需求乘 Richmond 24 小时倍率 |
| 需求分辨率 | 常数复制 | 每小时倍率用 `repelem(...,12)` 转成 288 个 5 分钟点 |
| 24 小时运行输入 | 主仿真按需要截取，但测试只覆盖 12 小时闭环 | 明确强制 288 个输出使用 575 个连续输入点 |

| 最后一次优化 | 未对 24 小时完整运行作显式审计 | 明确记录并测试输入索引 `288:575` |

以下部分从 Basic 1.1.1 原样保留：水位硬约束、单台二进制泵、46 kW 功率、0.050 m³/s 流量、电能成本、每次启停 0.20 AUD、精确动态规划求解器和 mock Decision 接口。Basic 1.1.1 已经删除的终端水位约束没有重新加入；Basic 1.2 仍不要求预测终点恢复到初始水位 2.30 m。

5. **扩展多泵前先重审求解器：**当前精确动态规划依赖“单台、固定流量、二进制泵”结构。若扩展到多泵、不同流量或连续转速，不能直接假定现有状态压缩仍然成立。
6. **建立公平基准：**现有灰色交替开关曲线只用于直观参考。正式报告经济节省时，需要匹配初末库存，并分别报告电能成本和启停成本。

## 真正的滚动时域逻辑

对 24 小时输出，`n_steps = 288`，预测时域 `N = 288`。每个采样点 `k = 1,...,288` 都执行：

1. 取连续的价格和需求窗口 `k:k+N-1`。
2. 以当前实测水位和上一实际泵状态重新求解完整 288 步二进制最优控制序列。
3. 只把 `u_plan(1)` 送给 Decision 接口。
4. 用实际执行流量和当前区间需求更新 `x(k+1)`。
5. 窗口向前移动一个 5 分钟采样点，再求解。

因此所需输入长度是

```text
n_steps + N - 1 = 288 + 288 - 1 = 575
```

第 1 次优化使用输入 `1:288`；第 288 次优化使用 `288:575`。需求把每日 288 点曲线循环扩展到 575 点。价格则从历史 CSV 连续跨日读取，**绝不复制第一天价格作为第二天价格**。

AEMO `SETTLEMENTDATE` 是 interval-ending 时间戳。运行日按 `(当日 00:00, 次日 00:00]` 解释：第 1 个控制区间结束于 00:05，第 288 个结束于次日 00:00。默认示例改为 **2026-02-09**：按显示日的 288 点统计，2026-02-09、02-20、02-24、02-27 都是 0 个负价区间；进一步按六联图实际使用的完整 575 点统计，2026-02-09 只有 **1** 个负价点，是所有合格起始日中的唯一最小值。因此该日期同时满足“当天负价最少”和“完整 0-48 小时输入负价最少”。24 小时显示使用价格时间 `2026-02-09 00:05` 至 `2026-02-10 00:00`；最后一次预测继续使用 `2026-02-10 00:00` 至 `2026-02-10 23:55`，共 288 点。

水位更新使用同一 interval-ending 区间的动作与需求：

```matlab
x(k+1) = x(k) + dt/area * (actual_flow_m3s(k) - demand_m3s(k));
```

## 图的含义

`run_basic_mpc` 生成包含六个子图的 `Basic_1_2_rolling_mpc_validation.png`：

1. `0-24 h price`：当前显示日实际采用的 AEMO 历史 RRP，对应输入 `1:288`。
2. `24-48 h price`：最后一个显示时刻仍能看到的完整 288 步价格窗，对应连续历史输入 `288:575`；它与第一张图只共享第 288 个边界采样点，没有复制第一天价格。
3. `Richmond demand`：25 L/s 基础需求乘以 24 小时倍率后的区间需求；每个小时平台都标注其 `d_m` 倍率，例如 `0.71x`。
4. `Pump on/off`：每次滚动优化只执行的首个二进制动作；灰线是继承的交替开关 price-blind 参考，不是公平的经济基准。
5. `Tank level`：实际执行流量和当前需求更新出的闭环水位；红虚线是硬约束。
6. `Cumulative cost`：实际动作产生的能耗费加启停成本累计值；它不是一次性 24 小时计划的预测成本。

由于原始倍率均值是 0.99625，交替参考的平均入流为 25 L/s，而平均需求为 24.90625 L/s；它会略微增加库存。因此该灰线只用于直观参考，不能直接当作严格等库存的节省率基准。
