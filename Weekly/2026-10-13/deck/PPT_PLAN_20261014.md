## 工具与一个已测出的渲染缺陷

预览路径是 `deck/preview_deck.py`,它包住 office-pptx 技能给的 LibreOffice Kit。

**缺陷:那套渲染把内容按 1.75 倍绘制,画布却按名义 dpi 出图,于是每张预览恒定裁掉右侧与下侧约 43%,`--dpi` 改不了。**

判据是对同一组已知几何量的测量,不是观察:

| 量 | 实际 | 名义 100 dpi 下 |
|---|---|---|
| 导航页深蓝条(0.16 英寸高) | 27 px | 16 px |
| 导航页琥珀条左缘(0.58 英寸) | 102 px | 58 px |
| 琥珀条右缘(2.78 英寸) | 485 px | 278 px |
| 页脚文字下缘(4.23 英寸) | 738 px | 423 px |

四处一致给出内容比例 **175 px/英寸**,而画布是 100 px/英寸。再把同一组标记放在 13.333 英寸页与 26.667 英寸页上各渲一次,两次的像素**完全相同**(条高都 27 px、左缘都 102 px),所以放大是绝对英寸的,与页面尺寸无关。四档 dpi(59 / 72 / 100 / 200)下内容比例恒为 1.72 至 1.75 倍 dpi,画布恒为 1 倍 dpi,两者同步,所以调 dpi 无效。

**绕法:** `preview_deck.py` 先复制一份 deck,把全部形状与字号乘 1/1.75,再以 dpi 175 渲染。内容缩到页面的 57%,渲染器的 1.75 倍刚好把它放回画布,整页可见,字号像素不变。判据:2334 px 宽的画布上内容跨度正好 2334 px(13.333 × 0.5714 × 307.6)。

那份缩放副本不进交付件,只用来出预览图。

### 0.3 公式渲染能力实测

`render_formula.py` 走 matplotlib 的 mathtext,本机没有 TeX 发行版。把计划要用的 74 个构造全部渲染了一遍,结论如下。

**可用并且渲染正确。**

```
\frac  \dfrac  \sum_{}^{}  \min  \max  \arg\min  \left( \right)  \sqrt{}
\hat{}  \bar{}  \tilde{}  \mathrm{}  \text{}  \operatorname{}  \mathbf{}  \mathcal{}
\mathbb{R}  \substack{a\\b}  \{ \}  \#  \mid  \top  \Delta  \times  \pm  \partial  \approx
\leftarrow  \vdots  \cdots  \ldots  \lfloor \rfloor  \|x\|  :=  D'_h  p^{\ast}
```

**不可用,必须在写公式前就避开。**

| 构造 | 报错 | 替代 |
|---|---|---|
| `\big` `\Big` `\bigg` | Unknown symbol | 用 `\left( \right)` 或直接圆括号 |
| `\tfrac` | Unknown symbol | 用 `\frac` |
| `\begin{cases} ... \end{cases}` | Unknown symbol | 用 `\substack{a\\b\\c}` 或拆成两张图 |
| `\le` | Unknown symbol | 用 `\leq` |
| `\overbrace` `\underbrace` | Unknown symbol | 不要用 |
| `\color` | Unknown symbol | 不要用 |

`\le` 这一条最阴:几乎所有手写 LaTeX 都会写 `\le`,而 mathtext 只认 `\leq`。计划里把它写进 linter 的正则。

透明度实测:全部渲染件 `alpha_min = 0`,角点全透明,无误。

## 5 公式规范

### 5.1 渲染

全部走 `Weekly/2026-09-23/deck/render_formula.py` 的 `render()`,参数固定 `fontsize=14` 到 `18`、`dpi=600`、透明底、墨色 `1B2430`。放图用 `deck_kit.add_formula`,它按渲染出来的自然尺寸放,只在超宽时按宽缩,不按宽拉。

### 5.2 禁用清单写进 linter

写一个 `lint_formulas.py`,在渲染前把每个公式串过一遍正则,命中即停:

```
\\big|\\Big|\\bigg|\\Bigg        花括号尺寸命令,mathtext 不认
\\tfrac                          用 \frac
\\begin|\\end                    cases 环境不可用
\\le(?![a-z])                    用 \leq
\\overbrace|\\underbrace         不支持
\\color                          不支持
\$\$|(?<!\\)\$                   公式串不带美元号,由渲染器自己加
```

### 5.3 三层检查

**第一层,渲染层。** 74 个公式串全部渲染一次,任何一条抛异常即失败。判据包括渲染成功、`alpha_min == 0`、墨色非空、宽高比落在 0.2 至 30 之间。

**第二层,样张层。** 全部公式拼成 3 张对照样张,每张一格公式一格名字,渲染成 PNG 后逐张看过。这一步是为了抓"渲染成功但显示不对"的情况,例如字号太小、上下标挤在一起、希腊字母缺字。

**第三层,成品层。** 成品 deck 里每一个公式贴图都必须过 `alpha_min == 0`,并且必须有一张符号表在它正下方若干英寸内。

### 5.4 文本里的下划线

用户点名过"不然又是下划线啥的非常难直接看明白"。判据做成机械的:deck 里任何文本 run 不得出现 `_` `^` `\` `$` `{` `}`。模型 key 一律写显示名:`T28_AR4` 只能以 `T28 + AR4` 出现,`ar_sel` 只能以文字描述出现。下标只允许存在于渲染出来的公式图里。

## 6 搬运的技术方案

### 6.1 做法

在 python-pptx 层做形状级深拷贝:

1. 目标 deck 用默认主题,`Blank` 版式,页面 12192000 x 6858000
2. 逐页读出源 slide 的 `spTree` 子元素,深拷贝进目标新页的 `spTree`
3. 图片按 `r:embed` 逐个加进目标包,并重映射 rId;同一张图重复出现时按内容哈希复用同一个 image part
4. 不搬母版、不搬版式、不改写 schemeClr

### 6.2 判据

- **页数**:四份合计 81,逐份核对
- **每页形状数**与源逐页相同
- **每页文字 run 序列**与源逐条相同,顺序也相同
- **每页图片数**与源相同,且每张图的字节内容按 sha256 与源媒体一致
- **几何**:每个形状的 left / top / width / height 与源逐 EMU 相同
- **颜色**:搬运后 slide XML 里 `schemeClr` 的出现次数与源相同,值相同
- **无新增**:目标页里不得出现源页没有的形状

源 deck 的页面宽度有一处差异:10-08 两份是 12191695,09 那两份是 12192000,相差 305 EMU,合 0.0003 英寸,低于自检容差 9525 EMU。形状按绝对 EMU 搬,不需要缩放。

### 6.3 清单文件

构建时必须落一份 `slide_origin.json`,逐页记录这一页来自哪份 deck 的第几页,还是新写的。自检脚本按这份清单分家族套判据:旧页允许有 `normAutofit`、允许不是 6 色、允许有 10 到 14 pt 之间的字号;新页一条都不允许。

## 7 数字纪律

新建 `deck_numbers_60d.py`,把 deck 里出现的每一个非结构性数字登记下来,每条带出处。出处一律指 `HANDOVER_60天7日图集_数据与结论_20261014.md` 的节号,或指 `官方合成值_数据与校验_20261014.md` 的节号。

自检做三件事:

1. deck 文本里抽出来的每个数字必须在登记表里,否则 FAIL
2. 同一个量在不同页给出的值必须一致,否则 FAIL
3. 每个数字必须能打印出它的出处行,作为人工复核的附件

## 8 自检清单

在 `check_deck.py` 的 9 项基础上改成 `check_deck_60d.py`,按家族套判据。

**两族共用**

- `bounds` 每个形状四边在页内
- `autofit` 新页不得出现 `normAutofit`
- `aspect` 每个图片的显示宽高比与原始像素宽高比一致
- `overlap` 图片与文本框交叠不超过文本框面积的 12%
- `density` 每页至少有一个字符或一张图

**只对新页**

- `type` 正文不低于 14 pt,注释档不低于 10 pt,标题不低于 24 pt,不得有 10 到 14 之间的中间档
- `palette` 所有 `srgbClr` 落在 6 个值内
- `formula` 每个公式贴图 `alpha_min == 0`
- `symbols` 每个公式贴图下方若干英寸内必须有一张符号表,且表里覆盖该页公式出现过的符号
- `scope` 每张图页必须有 `Scope` 散文与口径公式图各一
- `nodesc` 任何文本 run 不得出现 `_ ^ \ $ { }`
- `numbers` 全部可追到登记表,且同量同值

**渲染层**

- 逐页导出 PNG,新页 51 页逐页看,旧页抽 8 页看
- 导出 PDF 一份,总页数与清单一致
- 溢出风险排序:按字符数与框面积估一个溢出分数,分数最高的 15 页优先逐页看,其余用 2x2 拼版看

**收尾**

- `present` 交最终 pptx
- 汇报里写清楚自检过了哪几项、抽看了哪几页、哪一项没做

## 9 分阶段执行

每段结束停下汇报。

**S0 冻结与取数。** 写 `lint_formulas.py`,把 74 个公式串过 lint 加渲染,出 3 张样张;跑一次 MATLAB 取数作业补齐 D5 的 5 个模型,并顺带导出 16 个模型的 1 h / 24 h / 7.6 d 中位数与逐格普查份额;写成 `deck_numbers_60d.py`。产出:样张 3 张、数字登记表 1 份、取数日志。停下确认公式写法与数字。

**S1 搬运。** 写 `build_carry.py` 与 `verify_carry.py`,产出只含旧稿的 `deck_A.pptx` 与 `slide_origin.json`。判据全过才继续。抽 8 页导出 PNG 看一眼。停下汇报。

**S2 新内容骨架。** B0、B1、B2 九页,加两张示意图。导出这 9 页逐页看。停下汇报。

**S3 预测器二十页。** 一次做完,含公式与符号表。导出 20 页逐页看,重点看符号表有没有压到公式、公式有没有超宽。停下汇报。这一段预计最长,可能要拆两次。

**S4 图十五页。** 十二张现有图加图索引。导出逐页看。停下汇报。

**S5 结论与收尾。** B6、B7、B8 五页,然后合并成单一 deck。停下汇报。

**S6 全量自检。** 跑 `check_deck_60d.py`,逐页导出,导 PDF,算溢出分数排序,看完,交件。

依赖关系:S0 的数字表是 S2 至 S5 的输入;S1 的搬运与 S2 至 S5 的新页互不依赖,可以先做 S1 也可以并行;S6 依赖全部。
